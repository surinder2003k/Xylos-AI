Build a full-stack Next.js 15 backlink automation dashboard called "Xylos Backlinks". Single project, single Vercel deploy — no separate frontend/backend.

Tech stack:
- Next.js 15 App Router (frontend + API routes in one)
- Supabase (PostgreSQL database + authentication)
- Tailwind CSS + shadcn/ui components
- Cyberpunk Noir theme (bg: #0c0e12, red: #ff3131, orange: #ff5e00, cyan: #00f0ff, borders: rgba(59,73,75,0.2), text: #e2e2e8)
- Lucide icons
- node-cron for scheduling (runs in API routes)

Database schema (Supabase PostgreSQL):

-- profiles table (auto-created by Supabase Auth)

-- posts table
CREATE TABLE posts (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  title TEXT NOT NULL,
  url TEXT NOT NULL,
  excerpt TEXT,
  platforms TEXT[] NOT NULL, -- ['twitter', 'linkedin', 'reddit']
  status TEXT DEFAULT 'pending', -- pending, published, failed
  platform_results JSONB, -- { twitter: {success: true, id: '...'}, linkedin: {...} }
  scheduled_at TIMESTAMPTZ,
  published_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- schedule table
CREATE TABLE schedules (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  time_slot TEXT NOT NULL, -- '09:00', '14:00', '20:00'
  platforms TEXT[] NOT NULL,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- settings table (API keys, blog URL)
CREATE TABLE settings (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  twitter_api_key TEXT,
  twitter_api_secret TEXT,
  twitter_access_token TEXT,
  twitter_access_secret TEXT,
  linkedin_access_token TEXT,
  reddit_client_id TEXT,
  reddit_client_secret TEXT,
  reddit_username TEXT,
  medium_access_token TEXT,
  devto_api_key TEXT,
  blog_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id)
);

Features:
1. Authentication: Email/password login with Supabase Auth, session management
2. Dashboard: Stats cards (total posts, scheduled, success rate), recent activity list
3. Posts: Table view with title, URL, platforms, status, date. Manual "Post Now" button per row
4. Schedule: Set 2-3 daily time slots, choose which platforms per slot, toggle active/inactive
5. Settings: Secure API key inputs (masked), blog URL field, test connection button per platform
6. Platform posting:
   - Twitter: Use Twitter API v2 (OAuth 1.0a) to create tweet with blog title + URL
   - LinkedIn: Use LinkedIn API to create share post with link
   - Reddit: Use Reddit API to submit link post to chosen subreddit
   - Medium: Use Medium API to import/syndicate post with canonical URL
   - Dev.to: Use Dev.to API to publish article with source_url

API posting flow:
1. User clicks "Post Now" or cron triggers scheduled post
2. API route fetches post details from database
3. For each platform in platforms[]:
   a. Call platform-specific posting function
   b. Record success/failure in platform_results
   c. Update post status (published if all success, failed if any failed)
4. Log result to console
